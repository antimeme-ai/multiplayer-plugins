## P1 · Before release or submission

- **Strengthen OpenCode’s refusal boundary.** [OpenCode src/index.ts](../multiplayer-plugins/adapters/opencode/src/index.ts:181) scans values only and silently stops at depth eight. Credential fields supplied as separate object keys and values lose their context. Opaque board payloads are scanned as encoded text. Match the configured Multiplayer MCP namespace exactly, validate arguments by tool, inspect credential fields and decoded board content, and reject inputs that exceed inspection limits. Keep Outpost’s own guard as a second check. [OpenCode MCP tool naming](https://github.com/anomalyco/opencode/blob/v1.2.27/packages/opencode/src/mcp/index.ts#L571)
- **Fix cancellation and child errors in both runners.** [OpenClaw src/outpost.ts](../multiplayer-plugins/adapters/openclaw/src/outpost.ts:29), [Pi index.ts](../multiplayer-plugins/adapters/pi/index.ts:382). An already-aborted call spawns first and then accesses `timer` before initialization. Early stdin closure has no stream error handler, and stdout overflow silently truncates. Reject before spawning, install stream handlers before writing, and report overflow and cancellation explicitly.
- **Preserve card scope and inbox outcomes.** [OpenClaw card](../multiplayer-plugins/adapters/openclaw/index.ts:444), [Pi card](../multiplayer-plugins/adapters/pi/index.ts:768), [OpenClaw inbox](../multiplayer-plugins/adapters/openclaw/index.ts:644), [Pi inbox](../multiplayer-plugins/adapters/pi/index.ts:921). The native adapters post cards under `agent_card`, while MCP uses `party/main`. CLI returns cards as bridge envelopes, so the `kind === "agent_card"` renderer misses them. Match the canonical scope and recognize validated cards in bridge envelopes. Preserve skipped-drop and acknowledgement metadata so a decryption failure does not appear as an empty inbox. [MCP card scope](../multiplayer_outpost/crates/outpost-cli/src/mcp_bridge.rs:918), [CLI inbox output](../multiplayer_outpost/crates/outpost-cli/src/inbox.rs:1092)
- **Bind each Omarchy invite row to its own target.** [Panel.qml](../omarchy-multiplayer/Panel.qml:221) sends every row to bare `join`, which accepts the latest invite. Pass the clicked `partyId` and surface a join failure. [BarWidget.qml](../omarchy-multiplayer/BarWidget.qml:212) also retains stale secondary counts on failure and can restore inbox data after polling is disabled. Invalidate failed or superseded results.
- **Finish the Quattro UI bindings.** [Panel.qml](../omarchy-multiplayer/Panel.qml:27) reads `bar.foreground` where the host exposes `barForeground`. [BarWidget.qml](../omarchy-multiplayer/BarWidget.qml:284) packs the badge into a fixed icon slot, and its per-widget [IPC handler](../omarchy-multiplayer/BarWidget.qml:275) claims the same target on every monitor. Use the host color, lay out the count as a label, and register IPC once with a defined monitor policy. Expand [Model.js](../omarchy-multiplayer/Model.js:3) redaction to cover device-link tokens, credential records, and scheme-less invite links before displaying decrypted previews. [Quattro WidgetButton](https://github.com/omacom/omarchy/blob/v4.0.4/shell/Ui/WidgetButton.qml), [Quickshell IPC contract](https://quickshell.org/docs/v0.3.0/types/Quickshell.Io/IpcHandler/)
- **Finish package metadata.** Both `.omarchy/package.json` files use the supported legacy GitHub provider. New submissions are directed to `upstream.watch` with a version capture. Convert both and run the upstream checker. The OpenCode and Pi npm `files` lists reference missing READMEs. Add installation, supported-version, and verification instructions, then pack and load both tarballs in their host runtimes. [mp-outpost metadata](../multiplayer-packages/omarchy/omarchy-pkgs/pkgbuilds/mp-outpost-bin/.omarchy/package.json:3), [Blackbird metadata](../multiplayer-packages/omarchy/omarchy-pkgs/pkgbuilds/blackbird-bin/.omarchy/package.json:3), [OpenCode package](../multiplayer-plugins/adapters/opencode/package.json:11), [Pi package](../multiplayer-plugins/adapters/pi/package.json:8), [Omarchy upstream-watch spec](https://github.com/omacom/omarchy-pkgs/blob/master/docs/upstream-sources.md)

## P2 · Oracle strength and live-test checklist

The multi-host suite catches tool registration omissions, a few known secret patterns, literal fence markers, and card stdin transmission. It imports adapters directly, supplies MCP-shaped status and replay fields the CLI omits, and returns success for unrecognized argv. Those fixtures let the OpenCode load failure and native wire mismatches pass. Replace the permissive fallback with exact argv and byte assertions and use tagged Outpost responses as fixtures. Omarchy’s last test checks source strings, so it cannot detect missing QML properties, IPC registration conflicts, or failed-start behavior. [Multi-host fixture](../multiplayer-plugins/tests/test_multi_host_plugins.py:40), [OpenCode mock](../multiplayer-plugins/tests/test_multi_host_plugins.py:195), [Omarchy model test](../omarchy-multiplayer/test/model.test.mjs:135)

- **OpenClaw** — Install through the real loader. Check default and opt-in tool visibility, authenticated slash dispatch, and the `multiplayer` CLI. Read the same unread drop twice with default permissions and verify only explicit acknowledgement consumes it. Cancel a running wait and verify the child exits.
- **OpenCode** — Install the npm tarball in a clean profile. Verify the plugin alone discovers 17 MCP tools, then verify an explicit disabled or custom entry is preserved. Drive a clean call and a synthetic secret case through the real pre-hook. Confirm the latter produces no MCP `tools/call`, and confirm one provenance instruction in the provider prompt.
- **Pi** — Install the npm tarball and verify skill discovery, session status, slash commands, and schema enforcement. With two disposable peers, check replay versus live provenance, card rendering, binary board round-trip by digest, and secret refusal before execution.
- **Omarchy** — On Quattro, test missing binary, signed-out state, failed secondary requests, and recovery. Use two monitors and two pending invites to check IPC routing and row targeting. Verify repeated polling preserves unread drops and that inbox previews render literally with synthetic secrets redacted. On Arch, compare all three release archives to upstream hashes, inspect them with `bsdtar -tf`, and build and install each supported architecture in a clean chroot. Launch both binaries and install the theme from its public repo.

Live host loading, authenticated peer exchange, Quattro rendering, registry validation, and clean-chroot package installs remain open. No files were changed.
